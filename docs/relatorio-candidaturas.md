# Relatório — Currículo e Candidaturas (Fase 3)

## Atualizando o currículo

Revisei o meu currículo com foco em vagas de **desenvolvedor backend**,
destacando a stack que mais uso no dia a dia de estudo e prática: Node.js,
Express, PostgreSQL, autenticação com JWT e Docker. Reorganizei a seção de
projetos para colocar o **DoaCiclo** em primeiro lugar, já que é o trabalho
mais completo que tenho pronto hoje — cobre API, banco de dados, autenticação
e um fluxo de negócio real de ponta a ponta.

## Usando o DoaCiclo como destaque

Escolhi o DoaCiclo como principal item do currículo porque ele mostra, num
projeto só, várias competências que uma vaga de backend júnior/pleno costuma
pedir:

- Modelagem de banco de dados relacional (usuários, itens e solicitações,
  com relacionamentos e regras de status).
- API REST em Node.js/Express, com autenticação e autorização por papel
  (admin, doador, beneficiário) validadas no backend, não só escondidas na
  tela.
- Containerização com Docker e Docker Compose, subindo o ambiente completo
  com um único comando.
- Teste automatizado cobrindo o fluxo principal (cadastro → doação →
  solicitação → aprovação → entrega).

No currículo e nas mensagens de candidatura, linkei o repositório no GitHub
e resumi o projeto em uma ou duas frases, citando a stack e o problema real
que ele resolve, para ficar rápido de entender para quem está recrutando.

## Candidaturas no LinkedIn

Usei o LinkedIn para buscar vagas de **desenvolvedor(a) backend**, filtrando
por tecnologias compatíveis com o que já domino (Node.js/JavaScript) e por
nível de experiência compatível com o meu momento atual. Me candidatei a
algumas vagas nessa linha ao longo desta semana, anexando o currículo
atualizado e, quando o processo permitia mensagem para o recrutador,
mencionando o DoaCiclo como exemplo prático do que sei construir.

## Reflexão

Montar o currículo em cima de um projeto real ajudou a deixar as
candidaturas mais concretas: em vez de listar só tecnologias soltas, consigo
mostrar um sistema funcionando, com decisões de arquitetura que sei
explicar (por exemplo, por que um item reservado some da vitrine pública, ou
por que a validação de permissão fica no backend). Isso deixou o processo de
me candidatar mais rápido e mais confiante do que simplesmente enviar o
mesmo currículo genérico para todas as vagas.
